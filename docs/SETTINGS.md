# Local settings and diagnostics

Settings are helper-owned in `state/settings.json` beneath `%LOCALAPPDATA%\HalcyonXP\FirefoxDownloadManager`. The Firefox page retrieves them using protocol-v2 `get_settings`. A nonempty `update_settings` patch is validated again by the helper, applied synchronously to an exclusively owned inactive engine, and atomically persisted. A failed save restores the previous engine configuration. Pause all work first; otherwise `INVALID_SETTINGS` leaves the previous configuration intact. Existing task worker counts are intentionally unchanged.

Defaults: current user's Downloads folder, 4 workers, 16 global requests, 8 per-origin requests, 5 retries, keep partials on cancel/failure, verbose diagnostics off. Destination must exist and pass the same path/reparse checks as task creation. Global caps are 1–32, origin caps 1–8, retries 0–20, workers 1/2/4/8. Settings file version 2 accepts a version-1 record with absent verbose logging as false; unknown versions, fields, oversized/corrupt records, and unsafe filesystem entries fail closed. The internal settings version is independent of task-state and wire versions.

`keep_partial_on_cancel` selects the explicit cancellation command policy. `keep_partial_on_failure` controls engine terminal-failure cleanup; failed cleanup never becomes success. Removal always clearly confirms deletion of retained partials; it never deletes final downloads. Recovery/promotion failures retain safe state rather than deleting ambiguous output.

Diagnostics consist only of timestamp plus a fixed enum (`host_started`, `settings_applied`, `command_received`, `task_failed`). `command_received` is verbose-only. There is deliberately no raw text/URL/header/path logging API, so URL user-info, query values, referrers, cookies and authorization are excluded rather than heuristically redacted. Two atomic local files (`diagnostics.log`, `diagnostics.previous.log`) total at most 128 KiB. No upload exists. Logging failures are best effort and do not change download correctness. The existing stderr errors remain sanitized and contain no request payloads.

The state-store lock protects settings/log replacement. Temporary names are narrowly reserved, regular-file-checked, and recovered before replacement; unexpected reparse entries fail closed. Keep the per-user state directory private. A same-user attacker with access to the helper binary and state is outside the supported local isolation boundary.

If corrupt settings prevent connection, close Firefox/the helper, preserve `settings.json` for local inspection, then rename only that file to reset defaults. Never send task state or diagnostics to third parties without inspection: task state intentionally contains exact resumable URLs, unlike these enum-only logs.
