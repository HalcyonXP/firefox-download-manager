# Release qualification coverage and support boundaries

## Acceptance model

The owner-authorized outcome is a qualified MIT personal release on the existing native Windows 11 x64 / Firefox Developer Edition installation. Coverage is **layered**, not a claim that every Rust case runs through the browser or the packaged executable. The full pinned MSVC and distribution-target Rust suites, actual compiled-host process tests, exact-package native tests and actual Firefox tests must all pass. A narrower successful layer cannot waive a failure in another.

The distribution recipe runs Rust tests and then links executables with map output. Compiled-host integration tests are not automatically relabeled as exact-package tests merely because source/toolchain match; the separately identified artifact matrix establishes that boundary. No failing adversary is accepted by broadening its expected error set, discarding a failed run or retrying unchanged code until green.

## Accepted limits, not additional passed tests

- Targeted local observation: native AMD64, Windows11 `10.0.26200`, Developer Edition `156.0`/aurora. Hosted Server and ARM64 x64 emulation are separate evidence. Other OS/browser versions/architectures, a development-tools-free OS, enterprise policies and all proxy/TLS deployments are not qualified by these runs.
- ADR0011 replaced the unavailable separate clean-machine prerequisite with owned application/profile isolation on the owner's existing computer. It did not make that OS clean or waive functional/security tests.
- Unsigned helper and temporary packaged XPI; unchanged signing protection. Reload the temporary XPI after every Firefox restart. Hashes/MIT notices/provenance do not authenticate a publisher or replace review of an OS security warning.
- Same-artifact/same-version upgrade is not compatibility testing against a nonexistent earlier release. State migrations are explicit Rust fixture coverage.
- Strong validators justify retained byte identity within the documented HTTP contract; SHA-256 is optional content integrity, not a signature or malware scan. Published content is not continuously rehashed.
- Local account/OS trust compromise, malicious mapping/namespace mutation, hardware/power loss and hostile-account isolation are not claimed solved. Unknown/torn/changed authority is preserved and rejected, not guessed safe.
- Memory-only supplied session context is not secure erasure. Signed URLs and validators remain sensitive recovery data. Private/container/partitioned/ambiguous sessions, cross-origin context redirects and browser-request cloning are unsupported; revocation cannot retract already submitted context.
- The independently verified2GiB fixture records helper CPU, working set/private usage, aggregate I/O, file allocation and native event bytes/counts. It excludes OS cache/kernel/other processes; aggregate I/O is not disk-only, and loopback elapsed time is not Internet/VPN or physical-device throughput or a product ceiling.

Installation and troubleshooting are in `INSTALLATION.md`/`PACKAGE_SECURITY.md`. Final-main evidence and release/publication approval belong to #46, not this candidate table alone.
